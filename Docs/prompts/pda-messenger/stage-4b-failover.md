## 🎯 ЦЕЛЬ ЭТАПА 4b

Прозрачная деградация: если сервер недоступен или не подтверждает доставку, сообщение автоматически
уходит напрямую получателю (механика этапа 2), пользователь видит режим доставки.

### Дизайн (утверждён владельцем проекта; реализуй как описано)

1. Отправитель шлёт сообщение серверу и ждёт `ack` от получателя не дольше
   `malinov.messenger.relay_timeout_sec`.
2. Получатель всегда отвечает `ack` (адрес берётся из пакета) — и через сервер, и напрямую.
3. Нет адреса активного сервера ИЛИ ack не пришёл вовремя → немедленная повторная попытка напрямую
   (broadcast/direct механикой этапа 2). Только одна повторная попытка.
4. Прямая доставка тоже не удалась (получатель не в сети по кэшу анонсов) → ошибка «не в сети» в UI.
5. В UiState у сообщения отражается режим доставки: «через сервер» / «напрямую» / «не доставлено».
6. Повторные ack игнорируются (идемпотентность по паре «имя контакта + текст + время»).

## ✅ DEFINITION OF DONE (Этап 4b)

Все 5 команд гейта зелёные; vanilla не изменён. Интеграционные тесты:

1. **Сервер жив**: A→B через сервер; получен `ack`; у сообщения бейдж «через сервер».
2. **Сервер удалён до отправки**: A→B уходит напрямую; доставка успешна; бейдж «напрямую».
3. **Сервер умер между сообщениями**: первое доставлено через сервер, второе автоматически напрямую.
4. **Получатель вне сети**: ни сервер (нет в директории), ни прямая ветка не доставили → состояние
   «не доставлено», исключений нет.
